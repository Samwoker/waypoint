# Routing Subscriptions API

Routing Subscriptions link **Inbound Sources** to **Target Destinations** and control which event types are forwarded using wildcard filter patterns.

---

## 1. List Subscriptions

`GET /api/v1/subscriptions`

Retrieves all routing subscriptions for the authenticated tenant.

## 2. Create Routing Subscription

`POST /api/v1/subscriptions`

Creates a subscription connecting a Source to a Destination.

### Event Type Wildcard Patterns:
- `*`: Matches every event ingested by the source.
- `payment.*`: Matches `payment.created`, `payment.succeeded`, `payment.failed`.
- `order.item.*`: Matches `order.item.added`, `order.item.removed`.
- `customer.created`: Exact match only.

### Request Body:
```json
{
  "source_id": "2e38d7c0-ebaf-4441-b9da-5c35ff6e4a50",
  "destination_id": "9946ffcf-e7c7-427b-951c-7b3e0e482855",
  "event_types": ["payment.*", "charge.dispute.*"]
}
```

---

## 3. Pause & Resume Subscription

- **Pause**: `POST /api/v1/subscriptions/:id/pause` (Stops generating deliveries from new matching events).
- **Resume**: `POST /api/v1/subscriptions/:id/resume` (Re-enables routing).

---

## 4. Delete Subscription

`DELETE /api/v1/subscriptions/:id`

Permanently removes the subscription routing rule. Historical delivery traces generated by this subscription remain preserved in the audit log.
